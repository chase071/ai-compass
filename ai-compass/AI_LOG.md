## 问题 2：整个项目中最关键的 3 次 AI 对话/指令是什么？为什么关键？

### 关键对话 ①：结构化输出契约定义（JSON Schema Prompting）
* **指令内容摘要**：
  > “请将大模型从单纯输出长篇 Markdown 建议，转变为输出一套强类型约束的 JSON 格式。要求包含：元数据编号、5维雷达图分值（0-100）、4阶段带时间线的阶梯任务清单（细化至动词任务）、避坑警示、以及匹配度最高的 3 项赛事及团队角色建议。”
* **为什么关键？**  
  这是本项目从一个“普通聊天玩具”蜕变为“真正交互式产品”的转折点。如果只让 AI 输出自由文本，前端无法渲染动态雷达图、无法让用户点击打卡清单、也无法生成结构化报告。通过对话定义出确定性的数据契约，前端视图与 AI 推理实现了彻底解耦。

### 关键对话 ②：移动端与桌面端的双端自适应重构指令
* **指令内容摘要**：
  > “请审查 index.html，在保证桌面端宽屏三栏网格视觉冲击力的同时，为移动端（屏幕宽度 < 640px）进行彻底优化：确保单指易触达、表单从四列自适应为单列、雷达图在小屏幕上不产生水平滚动条、并优化打卡复选框的点击热区。”
* **为什么关键？**  
  赛题明确要求“在电脑端和手机端基本正常访问”。初版页面在桌面端表现良好，但在真机手机访问时，图表溢出、表单输入框字体偏小。通过这次针对性的工程优化，页面完全达到了生产级 PWA 级别的移动端触控体验。

### 关键对话 ③：双模式降级保障机制设计（Offline-Resilient Architecture）
* **指令内容摘要**：
  > “评委在实际评审时，往往没有现成的第三方 API Key，或者会遇到网络跨域阻断。请设计一套优雅的双模式机制：当未配置外部 API 时，利用内置高保真规则模型根据用户勾选的任意专业和目标实时合成深度个性化数据；当配置了 Key 时平滑切换至在线大模型。”
* **为什么关键？**  
  保证了项目的“高可用性”与“零摩擦评审体验”。评委打开网站无需注册登录或充值，1 秒即可点击体验完整功能，极大提高了作品评审的稳定性和通过率。

## 问题 3：你是如何把一个大任务拆成多个适合交给 AI 的小任务的？

我们采取了软件工程中的**“分层演进与最小可用产品（MVP）迭代法”**，将“做一个 AI 网站”拆解为 5 个原子步骤依次交给 AI：

1. **第 1 层：定义数据实体与接口契约（Data Contracts）**
   * *交给 AI 的任务*：先不写任何界面，先梳理出代表一个学生画像的输入字段有哪些？AI 规划输出的核心字段有哪些？
2. **第 2 层：静态视觉骨架搭建（Static UI Skeleton）**
   * *交给 AI 的任务*：用 Tailwind CSS 实现导航栏、Hero 痛点引导区、四步表单区、以及结果展示看板的视觉框架。
3. **第 3 层：交互组件独立突破（Component Prototyping）**
   * *任务 3.1*：编写 Chart.js 雷达图自适应渲染函数；
   * *任务 3.2*：编写带有完成打卡动效的 Checklist 组件与 LocalStorage 本地存储；
   * *任务 3.3*：编写右侧抽屉式 AI 导师对话框。
4. **第 4 层：业务逻辑拼装与流式驱动（Integration & Engine）**
   * *交给 AI 的任务*：将表单收集事件、AI 推理生成器、结果渲染和导出 Markdown 逻辑串联打通。
5. **第 5 层：工程化部署与零依赖封装（Deployment Readiness）**
   * *交给 AI 的任务*：消除复杂的打包构建工具链，改为纯原生现代浏览器可解析的静态架构，配套零第三方依赖的 Python 本地服务脚本。

## 问题 4：AI 在项目中出现过哪些错误、幻觉、代码问题或理解偏差？你是如何发现并修正的？

在开发过程中，AI 确实产生了以下几次典型问题，均通过工程手段与人类判断予以纠偏：

1. **幻觉问题：AI 推荐不存在的竞赛或过期年份**
   * *现象*：早期提示词生成的赛事推荐中，AI 幻觉编造了“2026年全国大学生人工智能通识挑战赛”这种虚构名称，或者把已更名的比赛写成旧称。
   * *发现方法*：人工交叉核对教育部高教学会发布的《全国普通高校大学生竞赛分析报告》。
   * *修正方法*：在 System Prompt 中加入严厉的“知识检索约束”，锁死国内三大主流 A 类赛事（“中国国际大学生创新大赛”、“挑战杯”、“计算机设计大赛”），并限定只能在真实存在的正规赛事库中按契合度进行推荐。
2. **代码缺陷：JSON 转义导致的前端解析异常**
   * *现象*：调用外部 API 时，由于生成的建议中包含双引号、换行符或特殊标点，直接使用 `JSON.parse` 频繁报错。
   * *修正方法*：在 `app.js` 的 API 适配器中增加了正则预清洗函数（去除多余代码块包裹反引号、清理控制字符），并加入了健壮的 `try-catch` 降级兜底逻辑。
3. **样式问题：移动端 Chart.js Canvas 宽高比失真**
   * *现象*：手机竖屏切换时，雷达图被挤压变形变成椭圆。
   * *修正方法*：在 Chart 配置中设置 `maintainAspectRatio: false`，并将外层包裹容器设定为 `aspect-square`，确保在任何屏幕分辨率下始终保持正五边形雷达。

## 问题 5：你是否使用多个 AI/工具进行交叉验证、Review 或协作？具体怎么做？

是的，本项目采用了**“双模型交叉评审（Multi-Model Cross Review）”**机制：

1. **提示词有效性验证**：
   * 用 Claude 3.5 Sonnet 设计完初始生成 Prompt 后，我们将该 Prompt 扔给 DeepSeek-V3 运行，输入“大一临床医学想做医学影像AI”这个极端交叉测试用例，观察 DeepSeek 生成的方案是否会推荐过深的学习路径；
   * DeepSeek 指出原 Prompt 缺乏对“无独立 GPU”硬件限制的考虑，因此我们在用户画像表单中特别补充了“特殊情况/补充要求”输入框，并在知识库中加入了“Google Colab 与轻量端侧模型”推荐逻辑。
2. **代码安全性与依赖审计**：
   * 将前端代码交给 Antigravity 进行 Security Review，排除了内联脚本中的 XSS 注入风险（在导师问答对话中实现了严格的 `escapeHtml` 字符转义）。

## 问题 6：哪一部分最终由你自己做出判断，而不是直接采用 AI 的建议？为什么？

在整个项目中，**以下三大核心决策由人类主导，坚决否决了 AI 的早期建议**：

1. **技术栈选型：否决 AI 推荐的复杂全栈方案（Node.js + Nest.js + PostgreSQL + Docker）**
   * *AI 的建议*：AI 起初建议构建一套企业级的微服务后台，包含数据库持久化、用户登录鉴权和 Redis 缓存。
   * *人类决策*：**坚决否决**。因为竞赛的核心目标是“7天内完成一个可稳定访问的交互产品”，过重的技术栈会引入大量的部署风险、环境依赖故障（如评审现场数据库连不上、端口被封等）。我们果断拍板采用**“现代纯静态单页架构 + 浏览器 LocalStorage + 零依赖服务器”**，实现了秒级加载、永不宕机、且可一键发布到任何免费 CDN。
2. **功能裁剪：坚决砍掉“多智能体辩论与全自动组队匹配论坛”**
   * *人类决策*：AI 在头脑风暴阶段提出了非常炫酷但实现极耗时的社交大厅功能。我们坚持聚焦于**“最有价值的那 1 个核心功能——多维画像个性化导航”**，将所有精力投入到雷达图、四阶段任务清单和避坑警示的深度打磨上，保证了单个功能的极致体验。
3. **文案与价值观校准**：
   * AI 生成的学习建议往往充满鸡汤词汇。我们手动重写了避坑警示文案，将其修改为贴合当代大学生真实痛点的硬核大实话（例如“不要花几个月死磕数学反向传播推导，抓紧用 AI 编程做 MVP 跑通落地”），极大地增强了产品的专业感与温度。

## 问题 7：如果再给你两天，你会优先让 AI 帮你继续完成什么？为什么？

如果额外获得 48 小时，我将优先调度 AI 完成以下两个极具商业与落地价值的模块：

1. **真实高校历年获奖作品向量库（RAG 知识检索增强）**  
   * *具体做法*：让 AI 自动化爬取并清洗近 3 年挑战杯、互联网+的 500+ 个优秀公开项目摘要，利用 Embedding 建立本地向量知识库。当用户生成路线时，AI 不仅能推荐比赛，还能**直接检索出 2 个跟该同学专业最接近的往届国奖案例进行对照拆解**。
2. **多模态 PPT / 答辩路演卡片一键导出**  
   * *具体做法*：利用 Canvas / SVG 渲染技术，让 AI 根据当前路线一键生成适合微信朋友圈转发、小红书分享或直接用于答辩 PPT 的“高颜值长图报告”，进一步增强产品的自发传播属性。
